# Результаты: вариант 7 — метроном, атаки по спектральному потоку, темп по АКФ

## 1. Цель и постановка

Цель — реализовать конвейер обнаружения атак ритмического сигнала по
положительному спектральному потоку STA и оценить темп по автокорреляции
огибающей атак. Измеряемые показатели: средняя абсолютная погрешность
времени атак (мс), найденный темп (BPM) и его относительная ошибка (%);
дополнительно precision/recall/F1 при допуске 50 мс.

## 2. Команда запуска

```bash
cd lab19_variant07
../.venv/bin/python main.py --method all --input sounds --output results \
    --create-synth --hop-ms 10 --window-ms 40 --threshold 1.5 \
    --min-distance-ms 200 --seed 42
```

Проверено: `--help` выводит описание всех параметров; некорректные
входы завершаются с кодом 1 и понятным сообщением.

## 4. Часть Б: детекция и темп

Основные графики:

- `*_flux.png` — spectral flux (синяя линия), адаптивный порог
  (оранжевая пунктирная линия) и обнаруженные атаки (красные треугольники).
  Каждый щелчок даёт резкий положительный пик флюкса; при SNR 0 дБ и пороге
  1.2 появляются два лишних пика, при пороге 1.5 — ложных атак нет.
- `*_acf.png` — нормированная АКФ огибающей атак. Главный пик соответствует
  периоду следования щелчков: 600 мс (100 BPM), 500 мс (120 BPM),
  около 429 мс (140 BPM). Пики на кратных периодах (2T, 3T) не выбираются:
  среди пиков не ниже 60 % от максимума берётся самый короткий период.
  Это устраняет типичную октавную ошибку «60 вместо 120 BPM».

Обработанный WAV `*_detected.wav` содержит исходный сигнал с добавленными
короткими метками в момент обнаруженных атак; `*_comparison.png` показывает
до/после при одинаковых пределах по времени и амплитуде. Поскольку в
варианте 7 фильтрация не предусмотрена, АЧХ не строится.

Метрики основного прогона (порог 1.5, hop 10 мс, окно 40 мс):

| Сигнал | Атаки (обн./этал.) | BPM | Ошибка BPM | Ошибка атак | F1 |
| --- | --- | --- | --- | --- | --- |
| 100 BPM (синтез) | 16/16 | 100.00 | ~0.00 % | ~0.00 мс | 1.000 |
| 120 BPM (синтез) | 16/16 | 120.00 | ~0.00 % | ~0.00 мс | 1.000 |
| 120 BPM (внешний CC0) | 16/16 | 120.00 | ~0.00 % | ~0.00 мс | 1.000 |
| 140 BPM (синтез) | 16/16 | 139.79 | 0.15 % | 4.29 мс | 1.000 |

SNR реконструкции метронома по найденным атакам (относительно исходного
сигнала) для синтетических 100/120 BPM составляет около 54.8 дБ; для
140 BPM — 0.11 дБ, для внешнего файла — около 0 дБ, поскольку форма
модельного щелчка отличается от формы щелчка во внешней записи. Для
зашумлённых состояний в `experiments.csv` указан входной SNR 0/5/10 дБ.

## 5. Часть В: исследование параметров

Перебор: `hop_ms ∈ {5, 10, 20}`, `window_ms ∈ {20, 40, 60}`,
`threshold ∈ {1.2, 1.5, 2.0}` — 27 комбинаций на каждый из 7 сигналов/условий,
всего **189 экспериментов**. Результаты: `results/experiments.csv` и
5 графиков в `results/plots/`. Среднее время одного прогона около 0.019 с.

Наблюдения:

- **Шаг STA.** 5 мс даёт наименьшую ошибку времени (в среднем 0.30 мс),
  10 мс почти эквивалентен по F1 и вдвое дешевле по числу кадров,
  20 мс ухудшает временное разрешение (до ~10 мс при окне 60 мс).
- **Длина окна.** 20 мс лучше для коротких щелчков; 40 мс даёт среднюю
  ошибку ~0.6 мс; 60 мс сглаживает атаку и увеличивает ошибку до ~9.7 мс.
- **Порог.** Средний F1: 1.2 → 0.999 (две ложные атаки при SNR 0 дБ),
  1.5 → 1.000, 2.0 → 0.999 (один пропуск при hop 20 мс и окне 20 мс).

## 6. Рекомендации

Использовать **hop_ms = 5, window_ms = 20, threshold = 1.5** для максимальной
точности времени атак. Если важна скорость и расход памяти, допустимо
**hop_ms = 10, window_ms = 40, threshold = 1.5** — при тех же F1 = 1.000
и BPM = заданному ошибка атак остаётся в пределах единиц миллисекунд.
Порог 1.2 не рекомендуется при сильном шуме, порог 2.0 — при коротком окне.
Для реальных музыкальных фрагментов с более длинными атаками окно 40–60 мс
может оказаться предпочтительнее; выбирать его следует по `experiments.csv`.

## 7. Состав результатов и структурированная сводка

В `results/` есть WAV (`*_detected.wav`, зашумлённые состояния), PNG
(обзор, flux, АКФ, сравнение, зависимости), `experiments.csv`,
`*_metrics.json`, `*_onsets.csv`, `*_info.txt` и `summary.json`.
Файл `summary.json` имеет стабильную структуру с ключами `signals`, `best`,
`experiments_csv`, `plots`, `recommendations` и может читаться генератором
отчёта без парсинга логов.

Лучшая комбинация по усреднённым метрикам: hop 5 мс, окно 20 мс, порог 1.5;
средний F1 = 1.000, средняя ошибка BPM = 0.00 %, средняя погрешность
атак = 0.30 мс.

## 8. Отклонения и примечания

- Существенных отклонений от задания нет. АЧХ отсутствует осознанно:
  в варианте 7 нет фильтра; вместо неё построены и объяснены flux и АКФ.
- Библиотека librosa установлена, но в ключевом алгоритме не используется
  (все расчёты выполнены на NumPy/SciPy), что соответствует заданию.
- Для 24-битных WAV из libsndfile/scipy отсчёты приходят лево-сдвинутыми
  в `int32`, поэтому делитель `2**31`; путь для «сырых» 24-битных значений
  в младших битах (`2**23`) предусмотрен в `audioio._scale_integer`.
